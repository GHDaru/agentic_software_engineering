Exemplo do capítulo 13 — quanto custa uma tarefa aceita #

Dois scripts e dois livros de ponto. O primeiro script deriva as métricas de economia do capítulo; o segundo projeta o mesmo registro no formato do OpenTelemetry (OTel), com minimização provada por mutação.

Arquivo O que é
tarefas-064.jsonl cópia byte a byte de docs/records/tarefas.jsonl do Maestro na versão 19823c2 — o único ciclo que o livro de ponto mediu
sintetico.jsonl livro pequeno e redondo (três tarefas, quatro revisões) para conferir a conta à mão
economia.py custo por tipo, tokens com e sem cache, vereditos válidos e descartados, custo por tarefa aceita × ingênuo, retrabalho por tentativa × por linhagem, tempo de ciclo, órfãos
projetar_otel.py spans no formato OTel, nomes gen_ai.*, lista de permissão de campos e o portão que reprova se algo fora da lista sair

Proveniência da cópia (o hash tem de bater):

git -C <maestro> show 19823c2:docs/records/tarefas.jsonl | sha256sum
# 590ff5da4dcc8cf3d701f6ed359207d41628e76cea8e3bdd9e5a993b013f4c69
sha256sum tarefas-064.jsonl      # o mesmo valor

Como rodar #

Requisito: Python 3.8 ou mais novo, só biblioteca padrão. No Git Bash do Windows, onde python3 pode ser um atalho vazio, use python; se o console reclamar de codificação, exporte PYTHONUTF8=1.

cd livro/13-observabilidade-e-economia/exemplo
python3 economia.py                      # o livro do Maestro
python3 economia.py sintetico.jsonl      # o livro sintético
python3 projetar_otel.py                 # projeção OTel, minimizada
python3 projetar_otel.py --sem-filtro    # a mutação: tem de reprovar
python3 projetar_otel.py --json          # todos os spans, para inspecionar

A conta à mão. Implementações: A = 1,00; B#1 = 1,00 (reprovada); B#2 = 0,50 (aprovada); C = 1,00 (reprovada). Revisões: 4 × 0,20 = 0,80. Total = 4,30. Aceitas: A e B → 4,30 ÷ 2 = 2,15. Executadas: A, B, C → 4,30 ÷ 3 = 1,4333. A diferença é o preço de C, que foi paga e não aprovada. O "approved" que o gerente escreveu sobre C é descartado: gerente não é juiz. Retrabalho por linhagem = B#2 + a revisão de B#2 = 0,50 + 0,20 = 0,70.

Limite da linha 5(b), declarado: o script mede a linhagem a partir da primeira reprovação válida do livro até a aceitação seguinte. Serve para um ciclo com uma revisão de ciclo (o caso do Maestro); num livro com várias tarefas reprovadas em paralelo, a conta certa é por alvo, e fica como exercício.

python3 projetar_otel.py --sem-filtro — sai com código 1 #

A mutação desliga a lista de permissão. A última linha tem de ser:

✗ VAZOU atributo fora da lista de permissão: attempt×16, cost_start_usd×13, kind×16, note×4, reason×7, redoes×2, session×23, tokens_by_model×13, tokens_subagents×13

Se esta linha não aparecer, o portão de minimização é decoração (capítulo 10): ele não viu o vazamento que você provocou de propósito.

O que fazer com isto no seu time #

Troque o livro pelo seu. O formato mínimo de cada linha é ts, event (assigned, start, stop, verdict) e task_id; stop carrega attempt, kind, cost_usd e os tokens por categoria; verdict carrega verdict, by (o id da tarefa de revisão) e session. Qualquer harness que deixe ler o uso de tokens de uma sessão consegue gravar isso.
